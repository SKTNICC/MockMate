## 4. H01：权限、媒体与生命周期

按[人工步骤](M3人工真机测试步骤.md)逐项引导，不要求一次连续操作所有故障：

| 项目 | 用户动作 | 模型判定与证据 |
|---|---|---|
| 麦克风拒绝/恢复 | 系统App信息中手动拒绝，再返回录音；随后允许 | 拒绝时明确提示、无假录音/空上传/推进；恢复后实际可采集。系统可能终止App，应正常重开 |
| 播放中耳机变化 | 开始播题后拔/插耳机 | 记录实际路由/播放/错误状态，按既定中断约束判定；无非预期持续播放/自动录音 |
| 录音中来电 | 说几秒后用另一部电话呼入，结束后回App | 采集停止/中断状态、已封存片段可解释、无通话继续采集/自动提交，回到原题可操作 |
| 播放中来电 | 重播当前题时呼入一次 | 播放/焦点资源释放，返回可显式重播，旧回调不影响新播放 |
| 后台/旋转 | 核对未提交时切后台再回；旋转一次 | 原场/回合/核对文字保留，无重复上传/提交/推进；录音中切后台则停止并封存 |
| 静音/设备占用 | 采用短静音或被占用输入，逐项执行 | 明确空转写/不可录制，不提交空答案、不假装成功；真实ASR可能识别背景声，要保存实际结果而非硬判空 |

不以shell撤权失败判定功能失败，也不以Assume跳过判通过。设备所有者手动撤权后可复验。若人工触发失败，先保留当前场和证据，再定位最小修复，不让用户反复重录整场来掩盖问题。

## 5. H02：真人真实模型六题

用户实际听题并说话，每题用自己的话回答，必要例子使用虚构项目。至少一题重录、一题修改核对文字；每次用户确认后才提交。停止录音会自动上传/转写，不代表答案已提交；达到120秒同样只进入后续核对。已有实际120秒证据有效，未改变录音实现时不强迫用户重新等两分钟。

模型可分步提示“现在请回答第N题/修改后确认”，等用户完成该动作再核查状态，不自动点提交、不代答、不用设备TTS/fixture生成回答。界面操作若确有需要，遵守当前AGENTS的Terra委派；服务/日志/ADB优先使用专用工具。

结束核验：

1. 6主问全部回答、planned=answered=6、bank/generated各3，无提前结束或跳过冒充整场；追问计在所属主问。
2. ASR/TTS真实provider，已确认文字、原转写、核对修改和asr/asr_corrected来源一致。至少一题重录后的最终提交来自新take。
3. 追问最多一层，评分/报告引文来自实际已确认回答，不凭口音、音色、情绪评分，不能用test provider固定分值充当真实质量。
4. 报告可查看，引用可定位；退出再从历史重开原场/报告，ID不变。
5. 列真实调用尝试数、成功/失败/未知、重试、request id、时长及可得用量；合计不超过预算。未知费用不当作零费用。

## 6. H03：设备断连与提交恢复

D04仍缺设备通路层；手机USB reverse直连电脑，切Wi-Fi/飞行模式通常不会切断这条通路。不要用这种操作制造“断网已通过”。

优先由模型在隔离环境控制代理/通路故障，用户保持USB连接并操作；若使用拔USB方式，先约定注入点，短暂断开后尝试上传，再接回，由模型重新确认serial与reverse、验证同原场/原key恢复。只操作本App测试通路，不改电脑全局网络或制造真实供应商错误。

D02已隔离HTTP证明单答案/单推进，但设备刷新前杀进程未单列。模型在隔离服务丢响应并阻止刷新后，执行设备force-stop/冷启，再验证原操作恢复；不要求用户目测毫秒时序抢按。此项不消耗真实模型预算。若当前手机暂只用于真人整场，先保存真人证据，再做隔离设备用例，结束后恢复真实配置和fixture=false，避免混场。
