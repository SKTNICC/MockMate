## 2. 已确定规则与工程默认值

### 2.1 沿用的产品约束

- 简历、JD和确认计划仍为入口；正式主问题题库/AI各半、去重、审核及评价依据由服务端保证。
- 每次主答或追问回答分别最多120秒；播题、上传、识别、模型等待不计入作答时限。
- 正式模拟收尾后出报告。语音模式不增加实时评分，不按口音、音色、情绪或声纹评分；评价仍依据确认提交的文字。
- 现有文字模式继续可用。M3不增加数字人、自拍窗、视频、整界面录像、专项和画像，M4视频不上传的边界保持。

### 2.2 本方案选定的可配置工程基线

| 项目 | 工程基线与理由 |
|---|---|
| 交互 | 按回合录音，停止后一次转写；不做全双工、边说边判题或流式ASR |
| 倒计时 | 用户点开始且录音设备真正启动后计时；播放结束不擅自开始录音 |
| 到120秒 | 停止采集并保留音频，进入转写/核对；用户确认后提交，不直接自动作答 |
| 核对 | 显示原始转写，可修正识别错误；提交后冻结，修订来源可追踪 |
| 录音格式 | 客户端固定16kHz、单声道、PCM16LE；服务器用Python标准库`wave`封装成WAV供ASR |
| TTS | DeepSeek语音服务、默认`stella`；只播本场服务端选择的开场、已曝光问题、追问和收尾 |
| 生命周期 | M3只在前台录音/播报；离页、失焦、来电或切后台停止并保留已完成片段，回前台由用户继续 |
| 临时音频 | 本地保留到提交确定成功或显式放弃；服务端终态原始音频建议24小时清理，可配置且需在上线前确认 |

120秒是已确定产品上限；核对交互、音色和24小时等为本方案工程选择，不写成用户逐项批准的最终产品参数。当前不引入后台录音前台服务。

## 3. 语音服务与输入格式

### 3.1 官方接口核对（2026-11-20）

DeepSeek官方已提供独立ASR与TTS：ASR为整段文件识别，输入支持PCM WAV/Ogg Opus，限制120秒、8MiB；TTS支持HTTP或WebSocket。现有Chat Completions适配器不能直接接收录音。[ASR官方文档](https://api-docs.deepseek.com/guides/asr/) · [TTS官方文档](https://api-docs.deepseek.com/guides/tts/)

本方案选定：

- ASR：服务端`POST /v1/tools/asr`，`multipart`的`file`为经校验/封装的WAV；保留返回的转写、时长和request ID。
- TTS：服务端使用`wss://api.deepseek.com/v1/tools/tts`，一次发送完整允许播报文本，再发结束文本事件；接收PCM，只有收到明确的成功完成事件且音频校验通过才发布。这样可判定生成中断，客户端仍在完整音频就绪后播放，不做实时流式对话。
- 文字追问/评分：沿用已配置的DeepSeek文字adapter及M2校验，不把ASR结果直接当作已提交回答。

端点前缀单独处理：现有文字base URL为`https://api.deepseek.com`，语音路径含`/v1/tools/`；不要拼成双`/v1`或将语音请求发到`/chat/completions`。实现前重读官方完整章节，鉴权、错误、格式和完成事件按实际协议验证。

### 3.2 服务端配置（已实现）

继续使用现有`AI_PROVIDER/AI_BASE_URL/AI_MODEL/AI_API_KEY`处理文字。新增`SPEECH_PROVIDER=disabled|deepseek|test`、`SPEECH_BASE_URL=https://api.deepseek.com`、`SPEECH_API_KEY`、`TTS_VOICE_ID=stella`及语音超时/临时保留配置。`SPEECH_API_KEY`未填时，只有在speech provider明确为deepseek时按文档规定复用`AI_API_KEY`；这是同一供应商的显式配置继承，不是错误后降级。

启动校验必须识别语音配置不完整、未知音色和生产test配置；`disabled`时文字模式仍可启动，语音入口显示未配置。Key仅在服务端，Android不直连供应商、不接收Key。语音adapter独立于文字provider，使用成熟HTTP/WebSocket库并锁定经过验证的版本。

用户已要求M3真实DeepSeek调用和测试，执行模型无需再次询问是否使用真实模型。先做受控小样本验证，记录用量与次数；预算尚未明确，不进行压力、批量或无限重试。本轮文档编写不触发收费请求。

### 3.3 Android采集与服务器校验

采用`AudioRecord`读取PCM，不手写WAV头。创建前核对`getMinBufferSize`、初始化状态、实际采样率/声道/编码；不支持时明确报错，不把其他格式伪装成16kPCM。[AudioRecord官方参考](https://developer.android.com/reference/android/media/AudioRecord)

Android最多写入1,920,000个单声道样本，即3,840,000字节PCM。以单调时钟显示倒计时，同时以样本数量限制实际音频；跨重组不能重置计时，读缓冲不得使最终长度超过上限。停止后关闭采集与文件，再计算SHA-256和长度，进行原子提交/上传。

服务器固定解释为本项目的`pcm_s16le/16000/mono`协议：流式限制字节数、验证非空且长度为偶数，从字节数独立计算时长；拒绝伪元数据、超长和截断。用`wave`写入WAV并回读核对参数，不自行解析RIFF。不给用户上传任意编码音频的通用入口。

TTS接收的PCM按供应商协议校验并用`wave`封装；网络异常、缺少成功结束事件、无音频或不完整样本均不发布ready缓存。禁止用静音/固定语音伪装生成成功。

## 4. 用户流程与状态边界

```text
确认计划 → 选择语音场/读取原场 → 本场音频处理说明
 → 开场/题目播报 → 用户开始录音 → 停止或120秒到时
 → 本地片段已保存 → 上传与ASR → 转写核对
 → 用户确认提交 → 复用M2追问判定 → 追问或下一主问播报
 → 收尾 → M2报告/历史（显示回答来源）
```

| 情况 | 处理 |
|---|---|
| 播报失败 | 留在同回合，显示重试；允许用户显式看文字后作答，记录实际路径 |
| 麦克风拒绝/设备占用 | 保留当前题，给明确原因及重新授权/显式文字输入入口 |
| 静音或无有效转写 | 不提交空答案、不推进；可重录或显式改文字 |
| 转写超过4000码点 | 原始转写保留，提示核对并精简；不静默截断或拆成多次回答 |
| 用户重录 | 旧录音与旧ASR结果不覆盖新take；新take不撤销已提交答案 |
| 上传/提交超时 | 保存原文件摘要、body和key，恢复原操作；不能直接产生新答案 |
| 录音中离页/切后台 | 立即停止采集，封存已有片段为interrupted；回原回合可试听、转写或重录，不自动继续采集 |
| 进程被杀 | 已封存文件恢复；未完成临时文件识别为中断，不冒充完整120秒回答 |
| 服务端已到下一回合/早退 | 旧take及ASR可留元数据，但不能应用到当前回合或改变已结束场次 |

本地`VoiceUiState`可为`idle/tts_loading/playing/recording/local_ready/uploading/transcribing/review/submitting/interrupted/error`。它不扩展M2会话phase；ASR完成不改变`awaiting_answer`，只有原`submit_answer`事务推进。播放与录音互斥，不把扬声器播题重新录入用户回答。

申请`RECORD_AUDIO`运行时权限；录音/播放受生命周期与音频焦点管理。现有targetSdk35必须考虑Android15焦点条件，API30手机也要测试；暂停按钮同时处理本地媒体资源及服务端会话。[权限官方说明](https://developer.android.com/training/permissions/requesting) · [音频焦点](https://developer.android.com/media/optimize/audio-focus)

## 6. 共享API设计（已实现）

统一使用现有`/v1`、服务端会话鉴权、错误结构与`Idempotency-Key`。本表为V01契约基线；先修改`tools/m1/build_contracts.py`，再生成现有`contracts/m1/`、样例并同步两端。路径保留在原目录是当前生成工作流，不另建平行生成源。

| 方法与路径 | 输入/结果 | 规则 |
|---|---|---|
| 现有`POST /plans/{plan_id}/interviews` | 加可选mode，默认text | 返回原场规则保持；新voice场记录音频外发同意版本 |
| `GET /interviews/{sid}/turns/{tid}/voice-draft` | active_take、voice_revision、音频/转写任务摘要 | 仅本人已曝光回合；读取不自动启动ASR/TTS |
| `POST /interviews/{sid}/turns/{tid}/audio` | multipart：PCM文件、take_id、session_revision、expected_voice_revision、sha256、固定格式；201返回asset/voice_revision | 文件校验、CAS激活take和幂等回执；一次上传不提交答案 |
| `POST /audio-assets/{id}/transcriptions` | expected_voice_revision；202返回`JobDto` | 同版本已有任务重开原job；明确重试走已有job重试协议 |
| `GET /audio-assets/{id}/transcript` | 202处理中/200终态，原始text与revision/empty | owner检查；不写入answer、不推进会话 |
| `POST /interviews/{sid}/speech` | segment=`opening|turn|closing`，turn_id按需；202 job或200现有asset | 服务端取允许文本，禁止任意text输入与未来问题合成 |
| `GET /speech-assets/{id}`及`/content` | 状态/摘要；ready后鉴权音频流 | 无公开文件路径或永久公共URL；重播复用缓存 |
| 现有`POST /interviews/{sid}/answers` | 原revision/turn/text，加input_source、audio_asset_id、transcript_revision | 只在该提交事务冻结来源、保存答案和推进M2；原text请求保持兼容 |

新语音处理同意可扩展现有开场payload，但不能把旧文字同意默认为音频外发同意。`voice-draft`首次不存在返回voice_revision=0；音频激活CAS同一事务创建/锁定draft再提升revision。锁序统一为session→turn→voice_draft→asset/job，和既有准备/计划锁保持单向关系。

音频上传回执必须先可幂等重放，再处理离页UI；同take/key不同文件摘要拒绝。文件先写带随机ID的私有staging，再原子移动并提交元数据；失败清理孤儿，DB回滚不留下可访问文件。流式限制请求体，不能先无限读取再检查大小。

ASR/TTS重任务不能占用Android当前30秒HTTP写请求。请求只创建持久job，供应商调用在worker进行；客户端用现有JobWatch订阅并根据语音asset查结果。轮询停止/恢复遵循前后台，不因GET再计费。

## 7. worker、重试与费用边界

新增job kind建议用`audio_asr`、`audio_tts`，长度保持在现有`String(16)`内；target_id为相应asset ID，input_revision为asset内容版本。同步check constraint、Schema/DTO、路由、所有权查询、`inputs_current`、worker分发、重试与恢复，不把asset ID误当M2 session ID。

- ASR发布前重核owner/session/turn、active_take、voice_revision和job fencing；重录、跳过、提交、早退后的旧结果不能回写当前草稿。无需取消已经产生费用的供应商请求才能保证隔离。
- TTS缓存键含实际允许文本摘要、音色、provider/输出格式和adapter版本；本人已曝光内容才可生成。相同输入多次点击只建一个有效job；缓存原子发布，正在生成和错误时不返回半截文件。
- 本项目可以保证业务job/答案只推进一次；供应商未知回执后重试可能再次计费，不能宣称外部调用exactly-once。保留known/unknown调用记录，使用现有有限重试机制，显式动作后再试，避免隐藏无限重试。
- `JobWatch`/恢复上下文增加`sessionId/turnId/takeId/voice_revision`；每次挂起后、UI更新前核原scope。媒体回调也必须验证generation，旧播放完成不能给新问题自动开录音。
- ASR空文本与传输失败区分；过长文本不静默截断。TTS权限/鉴权/限流/超时/格式/未完成事件分层报错。错误码及可重试性在共享契约集中定义，不把所有异常映射为成功或通用toast。

文件按账号/session/turn/take隔离；不可将大音频Base64塞入Preferences。私有目录保存不可变录音及临时`.part`，使用成熟加密封装及Keystore，不自造加密协议；上传时流式解密，日志不含音频正文、Key或原始个人材料。

现有文件操作日志只记录摘要与元数据，不保存可恢复字节。M3必须补持久本地音频引用及完整性检查，冷启能用同文件/同key重发；找不到或解密失败时明确“本地录音不可恢复”，不能换空文件重发。

文件落盘完成后才标记local_ready；提交确定成功只清对应take的待提交状态。未知提交结果期间不能删录音或覆盖原body。账户退出清当前媒体/显示缓存，保留按原账号隔离的未决操作；B不能读取或重放A的录音。

服务端终态临时音频按可配置保留期清理；运行中租约、待转写/待确认的活跃引用不可被清理。过期后保留回答文字/来源元数据，重转写需显式重新上传；不要在M3做长期音频资料库。
