# 本地开发与验证

本说明对应开发基线。先看[工程进度](工程进度.md)，了解测试数据、U01和未完成验收项。

## 1. 获取代码与环境

```powershell
git clone https://github.com/SKTNICC/MockMate.git
cd MockMate
py -3.12 -m venv .work/venv
.work/venv/Scripts/python.exe -m pip install -r backend/requirements.txt
.work/venv/Scripts/python.exe -m pip install -r tools/m1/requirements.txt
```

准备Python3.12、PostgreSQL16、本机JDK21、Android SDK35及相应build-tools。SDK/JDK/数据库/虚拟环境不随源码上传；新电脑需自行安装。Gradle wrapper已包含，首次下载Gradle与依赖需要网络。

下面以Windows PowerShell为例。Linux/macOS使用`python3`、`.work/venv/bin/python`和`./gradlew`，其余路径/命令按平台调整；本项目尚未做完整跨平台运行验收。

## 2. 本机数据库与配置

先在**独立本机PostgreSQL实例**创建可登录角色`mockmate`与业务库`mockmate`。端口可自选，本文使用55432以匹配当前测试约定。角色/密码由开发者本机配置，不使用真实线上数据库。

复制配置：

```powershell
Copy-Item backend/.env.example backend/.env
```

在`backend/.env`填写本机值，示意如下（连接中的密码须按URL规则编码）：

```dotenv
APP_ENV=development
DATABASE_URL=postgresql+psycopg://mockmate:<本机密码>@127.0.0.1:55432/mockmate
PRIVATE_FILE_ROOT=./runtime/private
AI_PROVIDER=disabled
ALLOW_TEST_FIXTURES=false
M1_SAMPLE_CATALOG=false
```

`DATABASE_URL`不能留空。默认disabled可验证账户和手工材料等独立操作，AI任务会明确返回未配置。`.env`、原始材料和运行数据都被忽略；不要提交或将Key放入Android。

若要运行**合成测试数据**的完整计划流程，显式把以下三项改成：

```dotenv
AI_PROVIDER=test
ALLOW_TEST_FIXTURES=true
M1_SAMPLE_CATALOG=true
```

Java后端实习是带sample标记的开发样板；test provider与test_only题库不是正式AI或人工批准。生产环境禁止这些开关。

## 3. 迁移、种子、API与worker

在`backend/`目录执行，Python解释器使用刚创建的虚拟环境：

```powershell
cd backend
../.work/venv/Scripts/python.exe -m alembic upgrade head
../.work/venv/Scripts/python.exe -m alembic current
# 仅在上面的合成环境配置下：
../.work/venv/Scripts/python.exe -m app.cli seed --mode test
../.work/venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

另开终端，同样在`backend/`目录：

```powershell
../.work/venv/Scripts/python.exe -m app.workers.runner
```

检查`http://127.0.0.1:8000/healthz`与`/readyz`。没有worker时任务可以入队但不会完成。`seed --mode production`只做相应目录/待审数据准备，不等于内容已经真人批准或服务已经上线。

正式`review-packet/import-content`命令通过`--bank`、`--fact-cards`、`--reviews`接收你准备的离线文件，具体参数用`python -m app.cli --help`查看。当前许可待确认的正式内容仍在本地管理，不在公开仓库；不要拿合成fixture冒充正式批准。

## 4. Android构建与联调

设置本机`JAVA_HOME`为JDK21，Android Studio打开`android/`并配置SDK，或在不提交的`android/local.properties`填写本机`sdk.dir`。

```powershell
cd android
.\gradlew.bat --no-daemon :app:testDebugUnitTest assembleDebug
```

开发端点为`http://127.0.0.1:8000/v1`。真实手机USB联调在电脑执行：

```powershell
adb devices -l
adb reverse tcp:8000 tcp:8000
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.mockmate.app/.MainActivity
```

上面安装路径相对仓库根目录；若当前在`android/`，去掉路径前缀`android/`。`adb`不在PATH时用SDK里的完整路径。修改映射前检查原有映射，不覆盖其它任务；安装保留数据，签名冲突时不得擅自卸载/清数据。真实Key仅在服务端。

## 5. 验证命令与测试库隔离

### 契约与地基

在仓库根目录：

```powershell
.work/venv/Scripts/python.exe tools/m1/build_contracts.py --check
.work/venv/Scripts/python.exe tools/m1/validate_foundation.py
```

修改契约先改生成源，再执行不带`--check`的生成命令，并同步两端与回归。

### 后端集成测试

当前`tests/conftest.py`默认固定使用`127.0.0.1:55432`、角色`mockmate`、数据库`mockmate_test`。也可以在导入`app.*`前显式设置`MOCKMATE_TEST_DATABASE_URL`，指向回环主机上以`_test`结尾的独立库，例如：

```powershell
$env:MOCKMATE_TEST_DATABASE_URL = "postgresql+psycopg://mockmate:<密码>@127.0.0.1:5432/mockmate_m2_test"
try { ../.work/venv/Scripts/python.exe -m pytest tests -q }
finally { Remove-Item Env:MOCKMATE_TEST_DATABASE_URL }
```

conftest 会从同一 URL 派生应用与维护连接，只接受回环主机和`*_test`库名；重建 schema 前用`current_database()`复核，并拒绝与当前`DATABASE_URL`同名的开发库。测试库可预先由本机管理员创建；应用角色只需要在该测试库执行迁移和重建的权限。每次会话重建其schema并seed合成数据。**仅在独立本地测试实例运行**，不要改生产数据库认证或让该DSN指向共享数据。

当前为**192项**真实PostgreSQL测试。外部AI请求使用测试provider/模拟HTTP，不是收费模型调用。Docker Compose默认数据库端口5432，不满足默认55432测试DSN；不能直接把这套测试当成Compose已验证。

### M2 面试冒烟与迁移验证

API 与独立 worker 启动后，在`backend/`执行：

```powershell
../.work/venv/Scripts/python.exe scripts/e2e_m2_smoke.py --base-url http://127.0.0.1:8000/v1
```

脚本走合成六题闭环、两类来源追问、报告证据、历史重开和零回答早退，输出脱敏ID与逐项结果。

旧计划迁移验证需要本机可创建数据库的管理连接（脚本会创建并删除临时库，不触碰开发库）：

```powershell
$env:MOCKMATE_ADMIN_DATABASE_URL = "postgresql://postgres:<管理密码>@127.0.0.1:5432/postgres"
$env:DATABASE_URL = "postgresql+psycopg://mockmate:<密码>@127.0.0.1:5432/mockmate_m2_dev"
../.work/venv/Scripts/python.exe scripts/verify_m2_migration.py
```

脚本先升到`9b2c3d4e5f6a`，通过M1 HTTP创建并确认计划，再升到head，用原plan ID开场并执行一次追问任务。

### Android与设备

JVM单测及构建见第4节；只构建设备测试APK可运行`assembleDebugAndroidTest`。设备测试需要独立账号、对应后端/worker/测试数据，操作方式与保留数据约束见[Android说明](../../android/README.md)。

`tools/m1/e04_setup.py`会生成随机测试密码并输出带token的本机测试记录；该文件及代理日志只能放忽略的`outputs/`，不能公开。长时序代理与运行脚本只用于隔离测试，不可作为生产API入口。

## 6. 当前适用范围

本机验证以Windows、PostgreSQL16和Android11/API30设备为主；本次公开的是源码基线，不包含APK、SDK或数据库备份。Dockerfile/Compose尚未在本机实测，并有仓库级fixture挂载适配事项。正式HTTPS、生产签名、部署、真实AI与真实审核验收尚未完成。
