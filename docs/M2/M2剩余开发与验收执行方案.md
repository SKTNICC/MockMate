## 3. 产品规则与修改边界

- 面向实习/校招；Java 后端实习为开发样板。2/4/6 主问题、默认6题、每主问最多一次追问是当前可配置工程基线。
- 简历与 JD 必需，JD 可选内置模板；无企业工作经历、无项目的有效学生材料可用，不编造经历。
- 正式主问题题库/生成各半；追问不改变配额、主问题题号和原来源。重看不产生新问题或写请求。
- 正式模拟在收尾后展示评分和评语。进行中只返回当前允许的题目、已曝光问答及状态，不泄露未来题干/答案/量表。
- 正文 1–4000 个 Unicode 码点，换行和原话保留；四字节表情的前后端计数一致。
- 已提交回答不可被后来的编辑覆盖；材料更新不改变旧场快照和报告。准备或材料删除后，旧场按自身冻结数据和 `sessionId` 查阅。
- 未知回执继续核对原操作；明确失败才提供适用的重试或保留主回答继续。基础报告必须明确未评分，零回答不制造分数。
- 本阶段不增加语音、视频、数字人、录像、专项训练、长期画像或题库后台；文字作答不套用120秒音频上限。
- 不重建数据库、不清手机数据、不改原始题库、不自动推送/部署，不把 synthetic/test_only 写成真人审核。

## 6. M2-C01：普通材料写回隔离

### 6.1 先补真实调用链失败回归

使用受控延迟 Repository、现有 ViewModel 测试接缝或隔离 instrumentation，覆盖：

| 场景 | 延迟位置 | 断言 |
|---|---|---|
| P1 保存文本后切到 P2 | 创建/编辑201返回前 | P2 页面、材料、草稿、loading、提示均不被P1覆盖；P1服务端结果仍可重开 |
| P1 上传后返回/切页 | 上传201返回前 | 不回跳P1 Review，不把旧提取任务挂到P2；原operation结果可恢复 |
| 旧保存/上传失败 | 错误回执前离页 | 新页无旧错误或busy状态；原账号操作日志按真实结果处理 |
| A发起写入后登录B | 成功/错误/旧401返回前 | B会话、页面、草稿和任务不变；不得用B token重放A操作 |
| 同材料旧版本或离开又重入 | 请求发起后切导航代数/版本 | 旧回包不能当作新页面请求应用 |

测试驱动实际 `saveTextMaterial`/`uploadFile` 调用，而非只测一个 scope 比较器。保留修复前失败证据；当前分支已修时核对对应回归与调用链，不人为制造缺陷。

### 6.2 最小修改要求

- 发起前捕获原账号/会话/导航/准备或材料/版本；每个挂起点返回后、每项UI副作用之前重核原上下文。
- `replaceTop`、清草稿、全局材料、job、loading/message都受保护。不要在旧回包到达后重新捕获当前页面，把它当成原请求来源。
- 操作已在服务器成功，与是否允许改当前页面分开处理。保留原key和回执恢复能力；不以禁用返回、换key或清空pending解决隔离。
- 正常仍在原页时，保存→Review、上传→提取→核对必须保持；回归当前 `confirmProfile` 的错误和成功保护。
- 设备补一次真实上传延迟切页；TXT/PDF/DOCX选择器、同摘要重选和取消作为第8节的材料依赖验收，不扩展上传功能。

## 7. M2-C02/C03：完整旅程与恢复

### 7.1 先两题纵向，再六题

先用隔离合成环境验证两题：确认计划→App开场→输入并提交主答→追问或下一题→收尾→报告→从历史重开同场。成功后扩六题3+3，让两种来源各有一个追问。自动化可控制test provider的判定，但必须标明合成行为。

完整 App 路径应由 App 操作完成。HTTP脚本可以准备材料和已确认计划，不能提前把整场回答和报告写好后只打开页面充当完整旅程。增加可复跑测试时复用已有样例/网络接缝；不在生产代码放固定题目或测试旁路。

### 7.2 恢复与并发必须覆盖

- 已保存回答后丢2xx回执：原body、turn、revision、key重放后仍是同一answer/job，不多一条答案。
- 2xx收到后、首次详情GET前杀进程：从本账号日志及服务端状态恢复原场；不依赖页面内存。
- S1请求中切S2、A请求中换B：成功、失败和旧401均隔离；同场低revision详情、旧job attempt不能回退UI。
- 编辑草稿后离页/切后台/冷启：按账号＋session＋turn恢复。确认本次提交成功只清匹配草稿；另一设备提交不同答案时保留本机未提交文本供查看。
- 暂停时worker完成判定：回场反映最新服务端状态，仍有下一题时保留paused，结束时进入closed。
- 追问生成失败：保留主答，显示明确的重试或继续；早退后迟到追问不能重新打开场次。
- 报告失败/重试/基础报告竞争：每场只有一个可重开报告；基础报告无伪造评分；合法评分slot复用，失效slot按现有规则处理。
- 持久任务的锁、唯一约束、fencing和只读详情一致快照已有实现。只有新回归揭示缺陷才改，不重新拆分全部服务。

### 10.2 模拟器测试与关闭

- 先运行 `adb devices -l`、`emulator -list-avds`；确认没有同AVD/端口的既有实例。记录本次启动器PID、AVD及serial。
- 本轮使用项目专用 `MockMate_API30`、端口5582，对应 `emulator-5582`；开机后确认 `sys.boot_completed=1` 和API30。
- Windows后台启动使用 `Start-Process -WindowStyle Hidden`，日志重定向到忽略目录。可用 `-no-window -no-snapshot -no-audio` 跑已有设备测试，不需要修改AVD系统设置或wipe数据。
- `adb -s <serial> reverse tcp:8000 tcp:8000` 并核对 `reverse --list`；若隔离API使用其他电脑端口，应显式把手机8000映射至该端口，不能误连当前真实服务。
- 用 `install -r` 安装两包；保留既有数据。测试前确认账号/页面初态，不能为绕过失败擅自卸载/清数据。
- **测试与清理放同一个 `try/finally` 生命周期中**。清理只移除本次映射并对本次serial执行 `emu kill`；复查设备列表和所记录PID/子进程确已退出。测试失败也要清理。

已验证的设备测试命令（端口转发和安装完成后）：

```powershell
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
$serial = 'emulator-5582'
try {
    & $adb -s $serial shell am instrument -w -r -e class `
      'com.mockmate.app.M2EntryDeviceTest,com.mockmate.app.M2ReportScrollDeviceTest' `
      com.mockmate.app.test/androidx.test.runner.AndroidJUnitRunner
    # 同时检查输出中的OK(N tests)、失败堆栈和崩溃；adb退出0不是测试通过条件。
} finally {
    & $adb -s $serial reverse --remove tcp:8000
    & $adb -s $serial emu kill
}
```

实际开发补六题、恢复、换号等设备用例；上面两项只是已通过基线。真机验收也必须先确认目标serial并执行端口转发，保留设备数据，不能用模拟器代替真机。若需要人工式界面操作，遵循当前AGENTS的Terra委派；指定模型不可用时如实报告该部分限制，继续可执行的CLI/测试项。
