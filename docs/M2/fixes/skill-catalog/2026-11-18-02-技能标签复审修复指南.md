# MockMate 技能标签复审修复指南

本轮修复「替换技能」仍提交失效编码、材料确认迟到回包覆盖当前页面，以及技能选择器设备测试的模拟登录失败。完成后再更新本地联调环境，使真机可以读到目录和中文显示名。原方案和接口说明见[技能标签与 AI 解析修复指南](2026-11-18-01-技能标签与AI解析修复指南.md)。

开工前运行 `git status --short`、`git log -1 --oneline`，确认工作区已包含启用词表接口、AI 解析兜底、技能选择器和题库数量提示。复审时这些功能和更早的 M2、Toast 改动都在工作区。变更与未提交文件需一并交接。

| 顺序 | 优先级 | 交付目标 |
|---|---|---|
| 1 | P3 | 修好设备测试替身，使两个用例都能进入各自的业务页面 |
| 2 | P2 | 项目或 JD 的失效技能可以一次替换成功，保留其他有效选择 |
| 3 | P2 | 材料 A 确认回包晚到时，材料 B 的页面和编辑仍保持正常 |
| 4 | 联调 | 开发库显示中文技能名，运行中的 API 和 Worker 使用新版代码 |

## 1. 修复设备测试的模拟登录

复审运行原版 `SkillSelectorUiTest` 时，两个用例都在等待账号出现时超时。生产 API 客户端安装了 Ktor `HttpTimeout`，请求执行前会检查引擎能力。自定义 `FakeHttpEngine` 没有声明该能力，请求在模拟路由响应前就被拒绝。复审用临时副本补齐能力后，题库数量用例通过，技能选择用例进入了替换场景。[设备测试引擎](../../../../android/app/src/androidTest/java/com/mockmate/app/SkillSelectorUiTest.kt#L58) · [API 客户端配置](../../../../android/app/src/main/java/com/mockmate/app/core/network/ApiClient.kt#L66)

1. 在测试引擎导入 `io.ktor.client.plugins.HttpTimeout`，在现有属性旁新增 `override val supportedCapabilities = setOf(HttpTimeout.Plugin)`。生产客户端继续使用既有的请求超时配置。
2. 保留模拟登录和业务路由。需要时给登录阶段添加有意义的断言信息，失败时能看到 ViewModel 的错误码或提示。沿用现有测试超时，确保假引擎确实收到并完成登录请求。
3. 先验证两个用例都能越过登录。保留题库数量用例，它应展示「本场需要 3 道相关题库题，目前匹配到 1 道」，并能点回设置。技能用例随后增强为第 2 节要求的回归。

## 2. 修复多选「替换技能」保留失效编码

**复现**。用一个含 `legacy.removed` 和有效标签 `java.core` 的简历项目，加载启用词表后点「替换技能」，选择「Java 并发」并确定。当前弹窗把旧编码原样初始化为 `draftSelection`，多选只追加新项。界面继续显示「不可用标签」，提交时仍包含失效编码，服务端会拒绝确认。复审已在模拟器上验证旧标签确实保留。[替换入口与弹窗](../../../../android/app/src/main/java/com/mockmate/app/ui/screens/MaterialScreens.kt#L623) · [选择状态](../../../../android/app/src/main/java/com/mockmate/app/ui/screens/MaterialScreens.kt#L744)

### 实施步骤

1. 沿用核对页已经加载成功的 `availableSkills`，用其中的 `code` 建立可选集合。打开弹窗时，把当前已选编码与可选集合取交集，并保留合法选择的顺序。空词表保留现有「移除标签」入口。目录请求失败或仍在加载时，保留页面上的旧选择和重试入口。
2. 弹窗内搜索只改变显示列表，跨搜索的多选状态持续保留。点「确定」时，用当前完整目录再过一遍选中编码，避免弹窗打开期间目录变化留下失效值。把结果通过现有 `onChange` 提交给条目。点「取消」或返回应保持原条目。单选提交零个或一个，多选提交按顺序去重的编码。
3. 保留条目内容和原文证据。只调用现有编解码器提交 `skills[].code`、`projects[].skill_codes` 与 `requirements[].skill_codes`。后端继续验证启用词表和引用。词表在确认前再次变更时，沿用服务端指向具体条目的错误信息，刷新目录后允许重选。[现有编解码器](../../../../android/app/src/main/java/com/mockmate/app/ui/screens/ProfileDraft.kt) · [后端校验](../../../../backend/app/services/text.py#L110)

### 回归与验收

- 扩展 `reviewScreenSearchSelectUnavailableTagAndClear` 的项目样例，使其同时含 `legacy.removed` 与 `java.core`。模拟「替换技能 → 搜索并发 → 选择 → 确定」。断言「不可用标签」消失，「Java 基础」和「Java 并发」都保留。
- 给测试引擎加材料确认的模拟响应，捕获真实确认请求的 JSON。检查该项目 `skill_codes` 只有 `java.core` 和 `java.concurrency`，并验证保存成功提示或快照结果。原测试只断言新标签可见，会漏掉旧标签一同提交。[已有选择器用例](../../../../android/app/src/androidTest/java/com/mockmate/app/SkillSelectorUiTest.kt#L79)
- 补查 JD 多选、简历单选、取消替换、搜索后保留已选、主动清空和目录临时不可用。已有标签不会因读取目录失败被静默清掉。多选为空时按现有契约写空数组，单选为空写 `null`。

## 3. 材料确认回包按原页面归属更新

**复现**。在材料 A 点击确认，让 POST 成功，再停住 A 的快照列表或材料详情 GET。返回并打开材料 B，开始修改 B 的技能或原文引用，然后释放 A 的 GET。当前成功分支只查账号，A 的材料、快照、成功 Toast 和加载状态可能覆盖 B。该并发路径由代码复审发现，修复时用受控测试复现。[确认入口](../../../../android/app/src/main/java/com/mockmate/app/ui/AppViewModel.kt#L1200) · [迟到写入位置](../../../../android/app/src/main/java/com/mockmate/app/ui/AppViewModel.kt#L1245)

### 实施步骤

1. 发起前捕获 `pageSnapshot()`、`materialId` 和用于提交的材料 revision。确认页面是这个材料的核对页。沿用现有 `isScopeCurrent(page)`，它会校验账号、会话、导航代次和目标。最终写入前也检查当前材料 ID 和 revision 仍属于发起确认时的材料。
2. `performWrite` 继续完成原账号的成功回执、本地幂等记录清理和服务端保存。回执返回后先核对原页面，再决定是否发起后续 GET。快照和材料详情读取完成后、更新 UI 之前再核对一次。两个顺序等待之间也可提前退出，避免对已经离开的页面继续发请求。
3. 将最后一次校验和状态更新放在无挂起的主线程片段。旧响应不能写入 `material`、`snapshots`、`invalidSkillItemId` 或新页面的加载与提示。技能校验失败的错误提示、问题条目定位和目录刷新仍关联发起页面。现有会话失效处理按账号规则执行。回到 A 时用正常读取入口看到已确认快照。

### 回归与验收

- 用已有 Ktor 测试方式，在 ViewModel 正常 `confirmProfile` 路径用 `CompletableDeferred` 阻塞 A 的成功后 GET。切到 B 并等 B 加载，再释放 A。断言 B 的材料和快照仍属于 B，加载提示与消息不被 A 改写。查 A 的记录已完成，重开 A 能看到快照。
- 覆盖 POST 回来前切页，以及离开 A 后重新打开 A。相同材料但不同导航代次也要隔离。正常停留 A 时保存成功、失效标签错误时标记条目并刷新目录的路径仍通过。[目录和计划错误现有测试](../../../../android/app/src/test/java/com/mockmate/app/SkillCatalogAndPlanErrorTest.kt)

## 4. 更新本地联调环境

复审时本机 8000 端口的 OpenAPI 未包含 `/v1/skill-codes`，开发库 `mockmate_m2_dev` 的三条标签仍显示为编码。本节是本地生效步骤。若工作区或数据库已更新，先复核现况。

1. 词表表结构已存在。开发库已有样板词条时，只补显示名称即可。参考下面的可选 PowerShell 命令，从仓库根目录进入 `backend` 后运行。它复用本机 `.env`，校验开发库目标，读取仓库样板显示名，只修改已经存在且名称为空或等于编码的记录。已配置的名称和启用状态继续保留。数据库目标不同或缺少样板词条时，先核对环境和目录来源。[现有目录初始化](../../../../backend/app/cli.py#L38) · [样板显示名称](../../../../fixtures/m1/catalog.json#L20)

```powershell
@'
import json

from sqlalchemy import text

from app.cli import FIXTURES
from app.core.db import engine, session_scope
from app.models import SkillCode

target = "mockmate_m2_dev"
if engine.url.host not in {"127.0.0.1", "localhost", "::1"} or engine.url.database != target:
    raise SystemExit("Expected the local MockMate development database.")

fixture = json.loads((FIXTURES / "catalog.json").read_text(encoding="utf-8"))
with session_scope() as db:
    if db.scalar(text("select current_database()")) != target:
        raise SystemExit("Unexpected connected database.")
    for code, label in fixture["skill_code_labels"].items():
        row = db.get(SkillCode, code)
        if row is None:
            raise SystemExit(f"Missing existing skill label: {code}")
        if not (row.label or "").strip() or row.label.strip() == code:
            row.label = label
print("Local skill display labels verified.")
'@ | & ../.work/venv/Scripts/python.exe -
```

2. 按本地开发说明停止旧 API 和 Worker，再从当前代码分别启动两个进程。复核 `/readyz` 的数据库状态，然后检查运行中的 OpenAPI 是否出现新接口。Worker 也要更新，材料解析由它执行。[本地启动步骤](../../../overview/本地开发.md#L48)

```powershell
$api = 'http://127.0.0.1:8000'
$ready = Invoke-RestMethod "$api/readyz"
$spec = Invoke-RestMethod "$api/openapi.json"
if (-not $ready.database) { throw 'Database is not ready' }
if (-not $spec.paths.PSObject.Properties['/v1/skill-codes']) { throw 'Running API lacks the skill catalog route' }
```

3. 真机通过 USB 和既有 `adb reverse tcp:8000 tcp:8000` 连接新版 API，覆盖安装 Debug APK 后用已有测试账号进入材料核对。确认能看到「Java 基础」「Java 并发」「JUnit 测试」，再试替换、保存和重开。真实模型测试单独记录。优先用已授权的合成材料进行联调。[真机转发说明](../../../overview/本地开发.md#L84)

## 5. 运行检查并交付

在 `android` 目录执行。先用 `adb devices -l` 核实目标，把 `$device` 改成隔离测试设备的序列号。

```powershell
./gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
$device = 'emulator-5580'
& $adb -s $device install -r app/build/outputs/apk/debug/app-debug.apk
& $adb -s $device install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
& $adb -s $device shell am instrument -w -r -e class com.mockmate.app.SkillSelectorUiTest com.mockmate.app.test/androidx.test.runner.AndroidJUnitRunner
```

判断结果以 instrumentation 输出里的测试数量和失败数为准。复审基线为后端 209 项、Android JVM 98 项通过。保留 AI 未知编码过滤、原文证据校验与题库配额的既有回归。后端或契约有改动时，按原指南运行对应检查。[后端与契约回归命令](2026-11-18-01-技能标签与AI解析修复指南.md)
