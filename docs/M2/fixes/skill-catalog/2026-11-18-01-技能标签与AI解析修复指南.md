# MockMate 技能标签与 AI 解析修复指南

将材料核对页的「技能码」文本框改成「关联技能」选择器。App 和 AI 使用服务端同一份启用词表。AI 返回词表外的编码时，只清理该标签，原材料条目和有效原文证据照常保留。材料保存后，生成计划仍需满足题库与 AI 各半。

## 一、开始前核对现状

1. 在仓库根目录执行 `git status --short` 和 `git log -1 --oneline`。编写本指南时 HEAD 为 `52ed5ce`，工作区含 M2 复审修复和 Android Toast 修改。实施时保留这些改动，尤其留意双方都会改到 `MaterialScreens.kt`、`AppViewModel.kt`、`prompts.py` 与 `runner.py`。若换了工作区，先确认接到的是当前代码。
2. 手动输入问题在材料核对页。简历技能的 `code` 来自通用文本字段，项目和 JD 要求的 `skill_codes` 来自手输多值框，界面没有展示有效选项。[材料编辑组件](../../../../android/app/src/main/java/com/mockmate/app/ui/screens/MaterialScreens.kt#L483) · [资料编解码器](../../../../android/app/src/main/java/com/mockmate/app/ui/screens/ProfileDraft.kt)
3. AI 问题在解析 worker。它已读取启用编码用于事后校验，但调用 provider 时没有传词表。模型返回任一未知编码，`validate_profile` 会使整个解析失败。手动确认也使用此校验，因此存在同样的报错。[解析 worker](../../../../backend/app/workers/runner.py#L305) · [解析模板](../../../../backend/app/ai/prompts.py#L19) · [材料校验](../../../../backend/app/services/text.py#L60)

## 二、增加可选技能目录

### 服务端

1. 复用 PostgreSQL 的 `skill_codes` 表及现有 `code`、`label`、`enabled` 字段。添加目录读取函数，稳定排序，只返回启用记录。让查询允许编码的函数复用相同的启用规则，避免 App、AI、确认接口各维护一份名单。当前词表没有岗位关联字段，本轮显示通用的启用目录。[目录服务](../../../../backend/app/services/catalog.py#L28) · [数据模型](../../../../backend/app/models.py#L346)
2. 在现有 catalog 路由新增登录后可访问的 `GET /v1/skill-codes`，建议操作 ID 为 `listSkillCodes`。Pydantic DTO 和共享契约统一为 `{"items":[{"code":"java.core","label":"Java 基础"}]}`。空词表返回 200 和 `{"items":[]}`。沿用目录鉴权与错误格式。Android 增加对应 DTO、API 和 Repository 方法。接口可沿用 `GET /v1/roles` 的组织方式。[目录路由](../../../../backend/app/api/catalog_routes.py) · [后端 schema](../../../../backend/app/schemas.py) · [Android API](../../../../android/app/src/main/java/com/mockmate/app/core/network/ApiClient.kt#L225) · [仓库层](../../../../android/app/src/main/java/com/mockmate/app/data/Repository.kt#L84)
3. 样板词表为现有三个编码补上显示名称，`java.core → Java 基础`、`java.concurrency → Java 并发`、`test.junit → JUnit 测试`。现有 seed 会把 label 写成 code。建议在生成源补独立的显示名映射，保留当前 `skill_codes` 字符串数组，避免改动其他 fixture 消费方。seed 新建记录时使用显示名，已有空值或编码占位时补名，已有自定义名和启用状态应保留。旧环境由原 seed 路径更新，用于验证的 fixture 由生成器产出。这个方案可复用现有 schema。[种子入口](../../../../backend/app/cli.py#L38) · [契约和 fixture 生成源](../../../../tools/m1/build_contracts.py) · [现有词表示例](../../../../fixtures/m1/catalog.json#L15)

### 验收

- API 的未登录请求返回 401。登录后仅返回启用项，排序稳定，每项包含编码与显示名。覆盖启用、停用、空词表、重复执行 seed 和旧数据占位显示名。
- 启用或停用记录后，目录响应和解析、确认时使用的允许集合按同一规则变化。用户端不能创建或启用技能词条。

## 三、修复 AI 材料解析

1. 在 `_handle_parse` 为本次执行载入启用词表。通过 `AiProvider.parse_material` 把编码和名称传到 DeepSeek prompt，明确要求只输出给定编码，无法从原文可靠关联时返回空值。把 JSON 结构示例中的默认技能编码改为空，或只引用本次词表内真实存在的例子。当前提示里的「用于技能码命名」应改为「用于从词表中关联技能」。检查测试 provider、所有 fake 及 adapter 测试，统一接口。测试 provider 仍保持确定性。[Provider 实现](../../../../backend/app/ai/provider.py) · [解析提示词](../../../../backend/app/ai/prompts.py#L19)
2. 在解析 provider 返回之后、`validate_profile` 执行之前，加一处明确的技能标签清理。保留启用编码，去除未知或已停用编码；多选项去重并保留首个顺序。简历 `skills[].code` 无可用值时设为 `null`；简历 `projects[].skill_codes` 和 JD `requirements[].skill_codes` 无可用值时设为空数组。清理只触及这三个字段。保留条目 ID、名称、描述、引用、必需程度和原有任务版本语义。
3. AI adapter 的类型校验、材料类型、引用原文、`item_id`、JD 岗位级别及任务归属校验照常执行。词表外编码属于可剔除的标签；字段类型错误、引用不存在等原有错误仍应按现有流程提示。即使本次词表为空，结构和证据有效的材料仍可以解析成功。
4. 任务写入前继续使用现有 job fencing 和材料版本校验。模型调用期间词表可能变化，发布前可用最新启用集合再过滤一次，确保已经停用的标签尽量在写入前消除。人工确认仍按确认当时的启用词表校验。需要记录时只记录移除标签数，用户可直接在核对页补选，避免把材料和 AI 原始回复带入日志。

### 验收

- 模拟 DeepSeek 返回「Redis 缓存」和 `redis.cache`，测试词表只启用 `java.core`。解析任务成功、Redis 原文引用保留、未知标签清空。同一响应中的有效标签保留，多选重复标签只保留一次。
- 测简历单选、简历项目多选和 JD 要求多选，覆盖全部未知、部分未知、无标签与空词表。捕获模拟 HTTP 请求，确认 prompt 含本次启用词表且不含测试中停用项。无效原文引用依然失败，解析结果迟到不能覆盖已编辑材料。[Adapter 测试](../../../../backend/tests/test_ai_adapter.py) · [材料回归](../../../../backend/tests/test_materials.py#L180)

## 四、在 Android 用选择器替换手输框

1. 进入材料核对页时加载目录，沿用现有 Repository 调用和页面作用域检查。显示「关联技能（可选）」。选择器按显示名展示和搜索，编码仅用于提交和查找。简历中的单条技能允许选零个或一个，简历项目和 JD 显式要求允许多选。把已选技能用可移除标签显示，用户随时可以清除。
2. 建议让 `ItemDraft` 的选择状态使用明确的编码集合或列表。更新 `ProfileDraftCodec.parse/build/validate`，兼容后端已保存的 `code`、`skill_codes`，确认请求继续使用当前 JSON 形状。技能名称仍为普通可编辑原文内容。读取或编辑旧 JD 时保留条目 ID、证据和要求的必需程度。核对所有构造 `ItemDraft` 的调用及 JVM 测试。
3. 区分目录加载中、加载失败和成功但为空。加载失败给「重新加载技能」入口，保留当前编辑和现有选择。未选择技能的材料可继续确认。已经选了技能而目录暂不可用时保留选择，由服务端校验，用户也可主动移除。
4. 如果已载入的旧标签在成功返回的目录里消失，在对应条目显示「此技能标签已不可用」，提供移除或替换。用户清理标签后仍可保存原条目。目录缓存过期导致确认接口拒绝时，刷新目录并定位到问题条目。可沿用 `PROFILE_INVALID`，为词表校验扩展可机器读取的字符串详情，例如 `field=skill_codes`、`item_id=req-1`，旧客户端仍可展示原错误。已有合法快照、已确认计划、已保存报告保留原版本；用户若要修改已确认材料，按现有规则创建新版本再确认。[材料确认与快照](../../../../backend/app/services/materials.py#L283) · [Android 确认入口](../../../../android/app/src/main/java/com/mockmate/app/ui/AppViewModel.kt#L1103)
5. 目录刷新或 AI 解析结束时保留用户当前页的手动选择和编辑语义，尤其检查从另一材料页面返回的迟到响应。确认网络失败后沿用现有待确认操作的幂等处理，避免目录刷新静默更改已经发出的请求内容。

### 验收

- 从真实核对入口验证搜索、单选、多选、清除、无标签确认、旧标签失效处理、目录失败后重试。新 UI 只提交选择得到的编码，空值能正常序列化。通过同一材料保存后重开，验证已选名称正常回显。
- 测上一材料的目录或解析结果晚到，当前输入不被覆盖。测试服务端仍会拒绝人为构造的未知手填编码。扩展现有编解码测试，并用 Compose 或设备回归覆盖选择入口。[已有编解码测试](../../../../android/app/src/test/java/com/mockmate/app/ProfileDraftCodecTest.kt)

## 五、给题库覆盖不足一个明确出口

1. 沿用生成计划时的同步检查。已审核、岗位级别符合、与材料已关联、且去重后的题库题不足时，使用现有 `BANK_INSUFFICIENT`，从选题计算沿用 `required=N`、`available=M`。已有这个错误码的其他场景，例如 JD 缺少显式要求、审核变化或生成后校验失败，应保留各自原有解释，避免统一拼接错误数字。[计划前置检查](../../../../backend/app/services/preparations.py#L457) · [选题逻辑与数量详情](../../../../backend/app/services/bank.py#L294)
2. 在计划页把带数量的错误展示为「本场需要 3 道相关题库题，目前匹配到 1 道」一类可读提示。用户可回到准备检查材料关联，或在存在可行档位时回到设置选择较少主问题。若可用题为零，直接解释当前题库覆盖不足。显示的数字只取服务端返回值。当前允许 2、4、6 道主问题，对应至少 1、2、3 道相关题库题。保留已有全局 Toast 样式，用户可在计划页看到该问题和可执行入口。[计划页面](../../../../android/app/src/main/java/com/mockmate/app/ui/screens/PlanScreens.kt) · [错误详情 DTO](../../../../android/app/src/main/java/com/mockmate/app/data/Repository.kt#L35)
3. 技能词条扩充和题库内容补齐是独立工作。为了让 Redis 能参与正式选题，先确保该词条已启用，还需要有相同编码且符合审核条件的题。测试使用合成内容。保留正式题库审核、证据绑定、去重和各半配额，现有题库不足的同步检查仍在发出 AI 生成任务前执行。

### 验收

- 不关联技能的内容可以确认，并能复现题库不足时的可读提示。六题缺题时显示真实数量，较少题量可行时能回到设置。零匹配时无可行题量建议。
- 恢复相关标签且题库充足后，确认计划正常生成。六题仍为 3 道题库题加 3 道生成题，原材料引用与版本关联仍正确。[个性化选题回归](../../../../backend/tests/test_personalization.py) · [计划流程测试](../../../../backend/tests/test_plan_flow.py)

## 六、执行顺序与交付

1. **目录与共享契约**。先实现编解码与目录 GET，改契约生成源，再生成 OpenAPI、schema 和 fixture，补契约测试。若测试写死 endpoint 数量，按实际生成变更更新断言。
2. **AI 解析与人工确认**。接上 prompt 词表和 worker 清理，先跑模拟 HTTP 和后端回归。后端验证使用本机隔离测试库，历史工作区用 `mockmate_m2_test`。pytest 会重建目标 schema，先核对连接目标，测试 provider 和模拟 HTTP 够用。真实凭据沿用本机配置。[本地开发与测试](../../../overview/本地开发.md)
3. **Android 与计划提示**。实现选择器、目录失败和旧标签处理，再连本地 API 做设备验证。更新后端 API 和 worker 后再装新版 Debug APK，确保客户端能拿到新目录接口。真机可用现有 `adb reverse tcp:8000 tcp:8000`。
