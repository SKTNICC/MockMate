# MockMate AI 返回数据修复复审与整改指南

复审对象为 `3e3b7a5` 上的当前工作区。后端在独立 PostgreSQL 测试库通过 240 个测试，Android 重新执行的 115 个 JVM 单元测试通过，Debug APK 构建、契约生成和地基检查通过。用当前代码只读检查上次真机的历史简历解析 Job，已经返回 `retryable=true`。本次未重试历史任务，也未调用真实模型或进行真机复验。以下发现需补专项回归，尤其是错误详情泄漏、非法字符持久化和工作经历证据错配。

先处理第 1 至 3 节的数据边界，再修复任务恢复及 Android。现有简历字段示例、语义复核阻断、计划 3+3、槽位续跑、追问和评分严格类型继续纳入回归。

## 1. 模型自定义字段进入错误详情、调用记录和纠正提示（P1）

**已复现。** 在合法的 `work_experience[0]` 对象内多返回一个键 `SYNTHETIC_MARKER_7469`。Pydantic 把未知键放入 `loc`，`_safe_validation_details` 原样拼入 `field=` 和字段错误。Worker 只检查路径的字符形状，该标记既能进入错误详情与调用记录的 `field_paths`，也能进入下一次请求的纠正提示。Android 对这类 ASCII 字段路径同样放行。另一个探针确认，HTTP 响应的 `usage` 对象可以附带任意键并通过 Provider，Worker 会保存整个对象。[Provider 字段摘要](../../../../backend/app/ai/provider.py#L148) · [Worker 反馈与记录](../../../../backend/app/workers/runner.py#L233) · [Job API 投影](../../../../backend/app/services/jobs.py#L410) · [Android 诊断过滤](../../../../android/app/src/main/java/com/mockmate/app/ui/ErrorDiagnostics.kt#L468)

1. 在模型边界生成安全摘要，只保留该阶段 schema 中的已知路径、数组下标、固定错误类型和固定描述。遇到 `extra_forbidden` 时报告合法父路径与恒定占位符 `extra_field`。合法缺失路径如 `work_experience.0.organization` 仍可展示。读取 Pydantic 错误时省略 `input`、`ctx` 和文档链接，避免把模型字段名或自定义验证器消息拼入摘要。
2. Job 错误、调用记录与纠正反馈复用该摘要。模型提供的 `item_id`、`requirement_id`、`dimension_id` 只有经当前材料或量表确认才保留，未知时记录字段类别和数量。把 `usage` 投影为支持的用量字段，逐个验证为非负整数。外部请求 ID 只接受约定格式的短字符串，遇到结构或超长值可省略。
3. 历史 Job 读出也要兼容过滤。API 保持 `ErrorInfo.details` 为字符串列表，已知旧消息和合法路径继续可读，未知消息在 Android 开发者面板和剪贴板用通用描述。保留截图类型历史 Job 的重试识别。
4. 回归用不同合成标记模拟未知键、未知 ID 和 `usage` 的附加值。断言 Job API、持久化调用记录、日志、纠正请求及诊断复制均无标记。补历史缺值正例，确认仍可看到 `organization`、`title` 两处缺失，且任务仍能重试。

## 2. JSON 空字符绕过校验并阻断入库（P1）

**已复现。** 在工作经历的 `description` 中放入 JSON 转义 `\u0000`。DeepSeek 模拟响应、`ResumeProfile` 和 `validate_profile` 都通过；在本地 PostgreSQL 只读事务对同一合成对象执行 `SELECT CAST(:payload AS jsonb)`，得到 `UntranslatableCharacter`。经实际写入路径会落到 Worker 的 `INTERNAL_ERROR` 兜底。其它阶段也从同一入口接收自由文本。[JSON 入口](../../../../backend/app/ai/provider.py#L1089) · [解析写入](../../../../backend/app/workers/runner.py#L724) · [Worker 兜底](../../../../backend/app/workers/runner.py#L187)

1. 在严格 JSON 解码之后、阶段模型校验之前，验证 JSON 对象键和各层字符串。发现解码后的 U+0000 或无法编码为有效 UTF-8 的内容时，以稳定原因 `reason=invalid_json_text` 返回 `AI_INVALID_OUTPUT`。保留合法中文、换行、制表符、emoji 和普通字面转义字符。引用保持原样，避免删改字符来通过匹配。
2. 保留现有重键、非有限数字和中断分类。新增原因接入有预算限制的纠正及第 4 节的重试策略。异常时保留材料原文、回答和有效槽位。诊断元数据还需经过第 1 节的独立投影。
3. 适配器测试覆盖嵌套字符串、对象键、合法 emoji 和孤立 surrogate。材料集成测试模拟两次都返回非法字符，确认结果为模型输出非法、草稿为空、原文仍在，之后同一 Job 显式重试可成功。添加一处追问或评分自由文本回归，验证共同入口会拦截。

## 3. 工作经历可以拼接两个条目中的事实（P1）

**已复现。** 简历原文包含两段。

```text
示例甲实验室｜后端实习生｜维护库存接口
示例乙银行｜数据实习生｜开发台账工具
```

把组织填为“示例甲实验室”，职务填为“数据实习生”，引用设为第二段原文。当前校验在整份简历里分别查组织和职务，再单独判断引文是原文子串，因此拼出来的工作经历可保存为待核对草稿。用户若直接确认，错误关联会进入后续匹配和出题。[工作经历证据校验](../../../../backend/app/services/text.py#L164)

1. 将 AI 填写的组织和职务绑定到同一段经历的引文。在解析提示词写明该条 `evidence.quote` 需连续覆盖组织和职务，可跨连续行。校验先按原字符做子串检查，再用现有归一化逻辑在该条引文内检查组织和职务。对原文能清楚分隔的多段经历，限制引文落在同一段，覆盖两段的长引文不能作为一条经历的依据。对于版式确实难以判断的材料，引导人工核对。给 PDF 抽取产生的合法空格、换行及标点差异补正例。
2. 同条证据不足时沿用 `ungrounded_work_experience` 做一次有针对性的纠正。仍缺必要事实时允许用户核对。避免自动填头衔或省略已识别的经历以换取解析成功。新的同条约束仅应用于 AI 解析，保留人工确认路径。
3. 加双组织双职务反例，同条多行正例，确实无工作经历的简历，以及第一次拼接错误且纠正成功的用例。反例分别覆盖短引文和把两段都包进长引文的情况。断言错误结果不落库，最终草稿的组织和职务有同一条证据支持。

## 4. 计划出题新增的格式错误未进入重试白名单（P2）

**已复现。** 以 `stage=plan`、`slot=generated-1` 调用现有判断，`invalid_json` 和 `empty_content` 可重试。 `duplicate_json_key`、`invalid_json_number` 和 `output_aborted` 返回不可重试。Provider 已细分这些原因，Worker 在有限纠正后也会保留原因，出题阶段仍用旧白名单。[出题格式重试](../../../../backend/app/services/jobs.py#L26) · [复核格式重试](../../../../backend/app/services/jobs.py#L339) · [槽位失败封装](../../../../backend/app/workers/runner.py#L1708)

1. 共用 Provider 的可恢复格式原因定义，按阶段明确允许项，至少纳入重键、非法数字、中断和第 2 节的非法字符。出题仍要求 `stage=plan`、有效槽位和当前输入，保留旧任务兼容及两次任务尝试上限。真实重复题、无效证据、语义复核不通过、鉴权和输入过期继续使用现有恢复策略。
2. 用 Worker 集成测试先成功写入一个槽，再让下一个槽连续返回重键。验证失败任务可用当前 `expected_attempt` 重试，状态查询维持只读；重试复用已验证槽，只补齐缺失槽，成功发布 3+3。再覆盖超过总次数、真实重复和版本过期。

## 5. 响应结束原因和参数兼容判断过宽（P2）

**已复现。** 显式返回 `finish_reason="unknown"` 和合法 JSON 时会被接受，因为已知兼容情况的缺省值也是同一个字符串。另一个探针返回 HTTP 400，正文为 `Invalid request: max_tokens parameter exceeds limit; thinking is enabled`。当前实现多发一次请求，并把这个 Provider 实例标记为不支持 `thinking`。后续同实例的出题可能直接跳过原本配置的 `thinking`。[结束原因处理](../../../../backend/app/ai/provider.py#L1006) · [参数回退](../../../../backend/app/ai/provider.py#L924)

1. 区分字段缺省与显式返回的供应商结束原因。保留已有 Mock 缺省结束字段的兼容，需要兼容 `null` 时单独定义并测试。显式 `"unknown"` 等未知字符串返回 `unknown_finish_reason`。继续拦截实际工具调用，兼容正常缺省与合法空列表。
2. 仅当错误明确指向 `thinking` 参数不被支持时做一次回退。优先根据结构化的参数名或错误码判断，纯文本兼容需要明确把“不支持”与该参数关联。无关 400 保持单次请求和原来的错误分类，避免改变 Provider 能力状态。真实回退继续记录实际 HTTP 次数。
3. 测试缺省、明确未知、正常结束、明确不支持和无关 400。对无关 400 断言请求次数为 1，并验证下一次合法请求仍会发送已配置的 `thinking`。

## 6. Android 重开核对页存在恢复竞态（P2）

**代码路径确认，待 Android 专项测试。** `openReview` 先导航和展示材料，随后才查询 `latest_job_id`。原文已有且无 profile 的历史失败任务，在 Job 查询返回前会短暂显示“AI 解析并生成结构”，查询失败时这一入口会一直出现。点击后仍会命中已有唯一任务。另一个时序是材料 GET 先返回 `uploaded`，提取在 Job GET 前完成。成功分支只重新投影 `parse`，因此核对页仍使用没有原文的旧材料。[核对页恢复](../../../../android/app/src/main/java/com/mockmate/app/ui/AppViewModel.kt#L953) · [按钮决策](../../../../android/app/src/main/java/com/mockmate/app/ui/screens/MaterialScreens.kt#L340) · [材料结果投影](../../../../android/app/src/main/java/com/mockmate/app/data/RestoreJobService.kt#L377)

1. 当前材料有最新任务 ID 且状态尚未查明时，暂停启动按钮，保留原文和可用的手动填写。查询失败时提供“查询任务状态”，只发送 GET。确认当前解析失败且后端允许重试时展示“重试 AI 解析”。
2. 成功的 `extract` 也进入现有材料结果投影。仅在页面资料仍缺原文或结果时重新读材料和快照，保留账号、页面、材料版本和 Job 尝试次数的保护，避免晚回调覆盖较新状态。
3. 用延迟 Job 响应测试加载状态、失败恢复与查询失败。再用 Fake API 依次返回无文本材料、已完成的提取 Job、带文本的材料，验证自动恢复到可解析状态。切页面、切材料和连续点击时也要验证没有重复排队或覆盖新状态。
