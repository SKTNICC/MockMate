# MockMate 简历键值表与边缘空列复查

上一轮横向 DOCX 抽取的章节顺序和行列保留有效，首尾都有竖线的 Markdown 表格也已识别。本轮 261 个后端测试、127 个 Android 单元测试、Debug APK 构建、契约和地基检查均通过。用合成文件和文本补测后，仍可复现两类正常经历被误拒绝。本轮没有调用真实模型或进行真机复验。修复沿用已保存的抽取文本作为引文来源，保留公开响应结构、人工核对和 Job 版本行为。

## 1. 两列键值型 DOCX 被误判成多个工作经历

用实际 `extract_text_from_file` 提取合成 DOCX。原文一张表只有一段经历，第一列为字段名，第二列为字段值。抽取得到以下连续文本。

```text
| 公司 | 示例甲实验室 |
| 职位 | 后端实习生 |
| 职责 | 维护接口，并对接示例乙银行。 |
```

用这三行作逐字引文，组织为“示例甲实验室”，职位为“后端实习生”。结构校验通过，`validate_profile` 报 `EVIDENCE_INVALID`、`reason=ungrounded_work_experience`、`field=quote`。横向表格中的同一条经历可通过。DOCX 已能保留行列，但分段逻辑将各双列行当作独立经历的起始行，导致这一段工作的公司和职位被分开。[DOCX 逐行抽取](../../../../backend/app/services/text.py#L1617) · [经历分段](../../../../backend/app/services/text.py#L695) · [单段引用校验](../../../../backend/app/services/text.py#L865)

### 修改与验收

1. 对两列的键值型布局复用已知“公司／职位／职责”等字段标签。按连续标签将一段经历的多行放在一起，对右列沿用完整字段值校验。可在抽取时统一成现有显式标签文本，也可让分段和字段提取共享键值行识别。重复一组公司与职位标签时划分新经历。
2. 字段键明确时才走键值版式。保留横向表头、普通两列项目表、空值和带换行的单元格行为。职责行中的合作单位不能作为公司值。
3. 用上传 API 和提取 Worker 覆盖合成 DOCX，再用模拟 DeepSeek 完成解析。正确经历可保存，职责里提到的公司不能替换单位。覆盖两段键值经历相邻、键值与横向表格混排、公司或职位为空。

## 2. 用每行的首尾竖线猜版式，导致有效列错位

用当前业务校验复现了两种正确结果失败。

| 原文版式 | 应采用的列 | 实际问题 |
| --- | --- | --- |
| 裸表表头为“编号／公司／职位／备注”，数据行用竖线分隔，首尾各有一个空单元格 | 空、示例甲实验室、后端实习生、空 | 行两端竖线被当成外框移除，剩余两列被左移 |
| Markdown 表头有完整外框与分隔行，数据行只保留左侧竖线 | 示例甲实验室、后端实习生、维护接口 | 左侧语法竖线被当作空数据列 |

复现文本如下。

```text
编号｜公司｜职位｜备注
｜示例甲实验室｜后端实习生｜
```

```text
| 公司 | 职位 | 职责 |
| --- | --- | --- |
| 示例甲实验室 | 后端实习生 | 维护接口
```

两个场景都让正确公司报 `field=organization`。全外框 Markdown 和横向 DOCX 对照例通过。`_split_table_line` 根据该行是否同时有首尾竖线决定删除哪两格，调用时没有表格版式信息。[逐行拆分](../../../../backend/app/services/text.py#L461) · [按表头取列](../../../../backend/app/services/text.py#L532)

### 修改与验收

1. 先根据所属表格的表头和分隔行确定外框规则，再解释数据行。明确为裸竖线的表保留边缘空单元格。明确为 Markdown 的表按其外框规则解释，允许数据行省略一侧边界。外框内的空值仍占原列位置。
2. 将同一份列结果用于分段和字段校验。转义竖线解码后仍维持原单元格。列数或边缘无法可靠判断时保留可核对的错误，避免丢弃不明字段后从职责中认领公司或职位。
3. 加裸表首尾同时为空、单边外框、双边外框、公司空首列、备注空末列和转义竖线用例。有效行按原位置通过，真正缺失的必填列仍返回字段错误。
