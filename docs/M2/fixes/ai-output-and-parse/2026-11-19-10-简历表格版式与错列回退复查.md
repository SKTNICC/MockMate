# MockMate 简历表格版式与错列回退复查

用当前代码重跑上轮三个复现样例。两列键值型 DOCX、裸表首尾空列、有完整外框表头的 Markdown 单侧数据行均能接受正确经历，并拦住职责中替换出的公司和职位。实测 262 个后端测试、127 个 Android 单元测试、Debug APK 构建及契约检查均通过。本轮用合成输入复现以下两个表格边界，没有调用真实模型或进行真机复验。修改保留当前 Job 恢复、已保存的材料原文、逐字引文和人工核对行为。

## 1. 表头无外侧竖线时，Markdown 分隔行未参与版式判断

```text
公司 | 职位 | 职责
--- | --- | ---
| 示例甲 | 后端实习生 | 为数据实习生编写手册，并对接示例乙银行。
```

用数据行作逐字引文，组织返回“示例甲”，职位返回“后端实习生”。`ResumeProfile` 通过，`validate_profile` 返回 `EVIDENCE_INVALID` 和 `field=organization`。表头两侧补上外框竖线后，保持同一数据行，正确结果通过。

分段和列绑定都跳过了 Markdown 分隔行，只看表头是否同时有两根外侧竖线。因此明确使用 Markdown 分隔行的表，会因为表头省略外框而被当成裸竖线表。数据行左侧的语法竖线就占了一个空列。仅引用数据行时，回查所属表通常只带回表头文本，也无法得知分隔行。[版式判断和行拆分](../../../../backend/app/services/text.py#L461) · [向上查找表头](../../../../backend/app/services/text.py#L663) · [表头继承与字段绑定](../../../../backend/app/services/text.py#L1230)

### 修改与验收

1. 在识别连续表格时，将表头和紧邻的有效 Markdown 分隔行一起用于确定版式。确认分隔行列数匹配。后续行使用同一规则解释可选外框与真实空列，避免根据每行重新猜测。
2. 将版式信息与表头列义传到分段、引用定位和字段绑定。引用只包含一行时仍需要拿到同一张表的上下文。无分隔行的裸竖线表继续保留真实的首尾空值。
3. 加无外框表头搭配仅左、仅右和双侧外框数据行的正例。保留错列值、实际缺公司或职位、裸表首尾空格、现有 PDF/DOCX 引文正反例。逐项检查证据位置和公司、职位读取结果。

## 2. 行列数异常时，明确表格退回宽松匹配

```text
公司｜职位｜职责｜备注
示例甲｜后端实习生｜为数据实习生编写手册｜对接示例乙银行。｜社团项目接口
```

表头四列，数据行由于中间内容带未转义竖线变成五列。当前校验接受正确的“示例甲／后端实习生”，也接受把公司替换为“示例乙银行”、或把职位替换为“数据实习生”。删除职责里未转义的分隔符、恢复四列后，两个替换结果都会被拦截。

当列数过多且最后一列是备注时，`_work_table_row_values` 返回空。调用处清除表头，后续按无表头文本校验。示例公司的名称也不会命中无表头公司列的后缀判断，于是回退到整条引文的子串匹配。这个回退允许职责里的实体进入待核对草稿。[行列数检查](../../../../backend/app/services/text.py#L560) · [表头失效分支](../../../../backend/app/services/text.py#L1273) · [经历字段校验](../../../../backend/app/services/text.py#L1310)

### 修改与验收

1. 区分“没有可用表头”和“表头已识别，但这行无法可靠对齐”。对后者先按明确规则处理外框、转义竖线、可确定的末尾职责分隔符和允许的尾部空列。列义仍无法确认时返回可恢复的证据错误，例如现有 `EVIDENCE_INVALID`、`reason=ungrounded_work_experience` 和 `field=quote`，走有限纠正或人工核对。
2. 决策需保留原表头存在的事实，防止其它校验分支随后将该行视为自由文本并放行。保留裸表、明确以职责为末列的原有可验证情况，以及职责中转义竖线的正常行。
3. 用上面的五列反例验收，确认两个替换字段都失败，行歧义不入草稿。继续验证合法四列表、转义后的职责、带备注的正常 DOCX，以及无表头自由文本。补用模拟 DeepSeek 的 Worker 用例，确认返回受控错误后原文仍在，用户仍可重试或手动核对。
