# MockMate 简历表格上传与校验复查

上一轮的裸竖线表头已能绑定公司和职位列，失效任务回读新增的退出重开与同页去重测试也已通过。本轮后端 259 项、Android 127 项测试通过，Debug APK 构建、契约和地基检查通过。用合成文件和文本复现了两个输入版式的表格约束缺口。修复范围是 DOCX 抽取与已有表头解析，沿用当前外部模型调用、原文引用、人工核对与 Job 版本约束。

## 1. 上传 DOCX 时，真实表格在抽取阶段丢失行列和原文顺序

用内存中的合成 DOCX 调用当前 `extract_text_from_file`。文档依次包含“工作经历”段落、一张有“公司／职位／职责”表头的表格、“项目经历”段落。表格的数据行是“示例甲／后端实习生／为数据实习生编写手册，并对接示例乙银行”。抽取后的文本把项目段落移到了工作表格前，再将每个单元格各放一行。

```text
工作经历
项目经历
模拟项目简介
公司
职位
职责
示例甲
后端实习生
为数据实习生编写手册，并对接示例乙银行。
```

把这份抽取文本交给现有 `ResumeProfile` 和 `validate_profile`，正确单位和职位可以通过。将单位替换为“示例乙银行”或将职位替换为“数据实习生”，并引用同一数据行对应的连续抽取文本，也能通过。现有实现先提取全部段落、再追加全部表格单元格。表头绑定只会处理带列分隔符的文本，所以实际 DOCX 上传绕过了上轮增加的表头保护。既有 DOCX 上传测试使用纯段落文件，未覆盖表格。[DOCX 抽取](../../../../backend/app/services/text.py#L1498) · [Worker 文件提取](../../../../backend/app/workers/runner.py#L438) · [既有上传测试](../../../../backend/tests/test_materials.py#L279)

### 建议实现

1. 按 DOCX 正文实际顺序遍历段落与表格。当前固定的 `python-docx` 版本已提供 `Document.iter_inner_content()`。段落保持现有行为，表格逐行生成可被现有表头校验消费的文本表示，保留列位置、空单元格和表格边界。若单元格含换行或分隔符，使用同一套可解析的转义规则保持单元格内容，避免文本换行后被识别为其他列或新工作经历。
2. 将抽取文本作为本次材料的统一引用来源。解析端、原文展示和 `validate_profile` 使用保存后的同一份文本，AI 引文须从其中逐字选择。兼容当前纯段落 DOCX、TXT 和 PDF 抽取。旧材料及已确认快照维持现有版本行为；需重新抽取原 DOCX 时，可由用户按当前重新上传流程生成一份新材料。
3. 在现有材料集成测试中添加合成 DOCX 表格，经上传、提取 Worker、材料 GET，再走模拟 DeepSeek 解析。断言表格仍处于正确章节，表头和数据行共享列义。正确工作经历可保存，职责里替换出的两个字段分别失败，错误结果不入草稿。额外覆盖含空任职列、单元格多行及正文里有多个表格的情况。

## 2. Markdown 表格的首尾竖线会让明确表头失效

下列合成文本保留同样的公司、职位和职责，使用标准的首尾竖线和表头分隔行。

```text
| 公司 | 职位 | 职责 |
| --- | --- | --- |
| 示例甲 | 后端实习生 | 为数据实习生编写手册，并对接示例乙银行。 |
```

当前 `_work_table_header_columns` 用竖线切分后，把首尾语法标记产生的空字符串当作空列，判定表头未识别。实际验证中，正确结果能通过，两个职责替换反例也能通过。去掉表头与数据行的外侧竖线及 Markdown 分隔行后，上轮修复能拦住反例。[表头拆分](../../../../backend/app/services/text.py#L416) · [行列提取](../../../../backend/app/services/text.py#L433) · [表头绑定](../../../../backend/app/services/text.py#L968)

### 建议实现

1. 共享表头与数据行的列解析。仅当表格确实使用包围式语法时，移除一对外侧竖线，并跳过对应的 Markdown 表头分隔行。保留真正的内部空列，也保留裸竖线版式中的首列或末列缺值。列式证据和段落判断使用同一解析结果。
2. 补首尾竖线、Markdown 分隔行、列顺序变化、空首列、空中间列、空末列、单元格内转义竖线的正反例。确认原先的裸竖线表格和跨章节截断仍正常，带明确表头的职责列只能作为职责证据。
