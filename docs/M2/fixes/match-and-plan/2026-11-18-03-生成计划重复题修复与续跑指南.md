# MockMate 生成计划重复题修复与续跑指南

本轮处理第 3 道 AI 题触发去重，以及两次尝试用完后如何继续生成六题计划。实施前用 `git status --short` 核对工作区，保留已在进行的匹配证据、计划 JSON 和错误页面改动。本轮重点是后续题的考察点分配和针对重复的纠正。[上一轮 JSON 修复指南](2026-11-18-02-生成计划JSON输出与任务恢复修复指南.md)

## 一、实际故障

按截图任务 ID 只读核对了本地开发库。准备版本仍为 4，材料与匹配报告已存在，题量为六道主问题，计划尚未发布。同一任务的两次尝试发生在不同阶段。

| 任务尝试 | 数据库记录 |
|---|---|
| 第 1 次 | `generated-1` 的两次调用都以 `AI_INVALID_OUTPUT` 结束，任务保存的最后原因是返回文本无法解析为 JSON。 |
| 第 2 次 | `generated-1` 和 `generated-2` 已通过校验并持久化。随后 `generated-3` 两次 DeepSeek 调用都返回可解析输出，`finish_reason=stop`。最后一次候选题被槽位去重拦截。 |

末次诊断只保存了候选题与冲突题干的前 40 字，两者前缀相同。这个冲突前缀只匹配已通过的 `generated-1`，本地题库没有匹配的前缀。服务器实际检查的是标准化全文相等，或全文二元分词相似度达到 `0.70`。现有记录无法区分命中了哪条规则，也无法仅凭前缀判断两道题的实际设问是否相同。模型调用记录的 `success` 表示 adapter 成功返回，业务校验仍由 Worker 执行。[槽位校验](../../../../backend/app/workers/runner.py#L1225) · [相似度实现](../../../../backend/app/services/planning.py#L67)

## 二、降低后续槽位重复出题

### 从已通过的题提取考察摘要

1. 在 `_handle_plan` 顺序处理槽位时，从已经通过校验且加入 `generated` 的题提取短摘要。使用槽位编号、`focus`、`topic_key` 和 anchor 的 `snapshot_id/item_id`。前序从缓存复用的合格题同样纳入摘要。保留现有完整 `avoid_stems` 和证据约束。[顺序生成和缓存](../../../../backend/app/workers/runner.py#L489) · [上下文构造](../../../../backend/app/services/preparations.py#L367)
2. 让 `generate_prompt` 明确后续题的选择顺序。优先选择仍与岗位要求相关且未充分覆盖的条目。材料较少时允许复用同一真实锚点，同时要求考察不同的实际作答任务。保留经历题和知识题的现有类型要求。没有合适的真实经历时，可按现有规则围绕明确的 JD 要求提出标注清楚的假设场景。
3. 题干直接给设问，只带必要背景。长段简历原话已经在 `anchors` 保存。举例用合成材料说明，若前一道题已问数据库访问的资源管理，后一题可以考察如何验证失败路径。只换项目名、题干开场措辞或挪动句子不足以构成新题。[生成提示词](../../../../backend/app/ai/prompts.py#L214)
4. 如果摘要只给模型作提示，继续重校验已有缓存后再复用。如果新增校验依赖摘要或考察点分配，则把相应字段纳入上下文摘要，并评估更新验证版本。不能直接复用材料、前序题或审核输入已变化的缓存。

### 重复时用唯一一次纠正重新出题

1. 在 `_validate_generated` 的重复分支附结构化原因，例如 `reason=duplicate_stem`、`duplicate_kind=exact` 或 `duplicate_kind=near`。近似重复可记录相似分和阈值。可可靠取得归属时附 `conflict_source=prior_generated` 或 `bank`、冲突槽位或题库 ID。新诊断用标识和分值即可，避免把私人简历原话带入诊断。
2. 给 `generate_prompt` 增加专用纠正分支。告诉模型上一题冲突的考察点或对应标识，本次要在**同一槽位**选不同任务，重出一条完整、合法的 JSON 题目。禁止题干继续由已有列表提供。保持原有锚点、证据、题目类型和评价依据要求。JSON 截断、空白、非法 JSON 的现有处理继续保留。[槽位纠正](../../../../backend/app/workers/runner.py#L1075) · [纠正提示](../../../../backend/app/ai/prompts.py#L332)
3. 保持单槽初次生成加最多一次纠正。两次均重复时保存最后一次结构化原因，未通过的题不写入已验证工作项。诊断中能看出 adapter 输出成功和槽位验证拒绝，避免把一次模型调用记成两次。可将校验结果附到同一调用记录或使用已有任务诊断字段。

## 三、保留去重规则与发布条件

1. 本轮先靠后续题选不同考察点修复，保留 `0.70` 阈值，以及槽位、计划两两对比、题库对比和语义复核。允许两个题共用技能或证据，条件是要求候选人完成的任务确实不同。[完整计划重复检查](../../../../backend/app/services/planning.py#L301) · [语义复核](../../../../backend/app/workers/runner.py#L646)
2. 如果之后拿到合成的完整题干，能复现「相同的长引文导致不同设问误判」，可单独评估只剥离由已验证 anchor 确认的固定导语。改动时在槽位与最终校验使用统一口径，保留全文精确查重、有效设问长度和语义复核，补充相同设问仍会拒绝的反例。本次前缀证据不足以改变规则。
3. 六题仍为三道题库题加三道 AI 题，所有题、证据、审核和语义检查通过后统一发布。已验证槽位可以留在失败任务的内部记录中，供仍有资格的重试复用。整份计划不会因为只生成两道 AI 题而发布。

## 四、处理已耗尽次数的任务

1. 截图任务已到第 2 次尝试，保留现有数据库和服务端上限。原任务可只读查询。本轮不通过数据库重置 attempt、手动补题或自动重跑。未耗尽次数的重试仍由服务端 `retryable` 决定，继续兼容上轮的输出格式恢复规则。[任务次数约束](../../../../backend/app/models.py#L221) · [重试资格](../../../../backend/app/services/jobs.py#L259)
2. 提供「沿用材料新建准备」出口，可复用 App 的 `redoPreparation()` 路径。先核对它可从未发布计划的页面调用。仅使用当前准备绑定的简历、JD 快照、岗位、级别与原题量，避免引用其他页面残留的快照。使用现有创建接口、幂等键与操作恢复。旧准备和旧失败记录保留，新准备使用自己的匹配报告，旧任务的槽位不跨准备移植。[已有新建准备逻辑](../../../../android/app/src/main/java/com/mockmate/app/ui/AppViewModel.kt#L1825)
3. 创建新准备由用户主动操作，而且只复制配置。仍由用户在正常流程发起匹配和生成六题。界面回包要核对账号与发起页面。若走现有手动流程验证，可新建同配置的准备并选择原来的两份已确认快照，无需重新上传材料或减少题量。
4. 根据 `reason=duplicate_stem` 展示「第 3 道 AI 题与本场已有题目过于相似，本次计划未发布。已确认的材料仍可复用。」能确认冲突来自题库时改用对应文案。兼容旧错误详情中的重复题干文案，只显示一张失败卡。次数耗尽显示「已用完 2 次生成尝试」，避免把初次生成也称为重试。[计划页面](../../../../android/app/src/main/java/com/mockmate/app/ui/screens/PlanScreens.kt#L429) · [错误映射](../../../../android/app/src/main/java/com/mockmate/app/ui/ErrorDiagnostics.kt#L174)

## 五、验收和交付

| 用例 | 通过条件 |
|---|---|
| 第 3 槽复制第 1 槽 | 模拟第 1、2 槽成功，第三槽首次返回重复题。纠正请求含冲突与已考察摘要，第二次返回不同题后发布 3+3。 |
| 纠正仍重复 | 第 3 槽只有两次调用，最终诊断包含原因与槽位。前两个工作项仍在，计划未发布。 |
| 题库与语义重复 | 完全重复、改名近似重复与语义复核发现的重复仍被拒绝。只共用一个锚点且要求不同作答任务的合成题能通过。 |
| 材料少与缓存复用 | 无工作经历或项目很少时，可以选择另一个真实考察点或 JD 假设场景。复用的合格槽位也纳入后续题的摘要。 |
| 已耗尽尝试 | 旧任务仅可查询。Android 显示单张失败卡与复用材料入口。检查新准备的快照、岗位级别和题量，创建时无 AI 调用。 |
| 已有功能 | JSON 格式错误恢复、证据校验、题库不足提示、计划确认和正式开场继续通过。 |

## 可复制给执行模型

> 按《MockMate 生成计划重复题修复与续跑指南》实现。用前序合格题的考察摘要约束后续出题，为重复题增加明确的同槽纠正。保留去重、语义复核、调用预算、任务上限和 3+3 配额。让已用完尝试的用户可沿用材料新建准备。覆盖第 3 槽与第 1 槽重复的完整回归，报告实跑结果。
