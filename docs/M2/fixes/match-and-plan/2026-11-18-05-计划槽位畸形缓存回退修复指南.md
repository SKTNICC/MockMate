# MockMate 计划槽位畸形缓存回退修复指南

本轮只处理上次复查发现的 P3。**缓存键匹配，但缓存题目缺字段或类型错误时，只重新生成该槽位。** 其他通过校验的题继续复用。上一轮已经验证了旧版与新版缓存键兼容，这次在原有缓存读取分支补一个异常出口。[跨版本缓存修复指南](2026-11-18-04-计划槽位缓存跨版本兼容修复指南.md)

## 一、问题在哪里

Worker 从当前任务读取已验证的槽位。它先核对缓存键、验证版本，以及 `question` 是否为字典，再调用 `_validate_generated`。如果 `question` 仍是字典但缺少必填的 `evaluation`，前置检查会通过，随后 `GeneratedQuestionOutput.model_validate` 抛出 Pydantic `ValidationError`。当前缓存分支只捕获 `AppError`，因此这种异常会交给 Worker 的通用失败处理，整项任务会以 `INTERNAL_ERROR` 结束。[缓存读取和回退](../../../../backend/app/workers/runner.py#L596) · [题目结构校验](../../../../backend/app/workers/runner.py#L1337) · [题目数据模型](../../../../backend/app/schemas.py#L507)

复查已用畸形字典离线确认会抛出 `ValidationError`。截图任务的两条真实旧缓存都通过了当前校验。回归使用隔离库里的合成记录。

## 二、修改方法

1. 在 [Worker](../../../../backend/app/workers/runner.py#L612) 导入 `from pydantic import ValidationError`。仅在**读取缓存并重新校验**的分支里，将 `except AppError:` 改为 `except (AppError, ValidationError):`，沿用现有 `reused = False` 回退。保留当前缓存键、历史键和验证版本的判断。
2. 继续用现有 `_generate_slot` 生成失效槽位。新题通过验证后，由 `_save_slot` 按当前实现写入新题、当前上下文键、验证版本和内容摘要。现有保存逻辑会按任务和槽位更新原记录，并检查准备版本与 Worker 租约。[Worker 槽位保存](../../../../backend/app/workers/runner.py#L1135) · [已验证工作项写入](../../../../backend/app/services/jobs.py#L463)
3. 让后续槽位继续基于本轮实际采纳的题构造摘要和禁止题干。坏缓存不应进入 `generated`，也不应进入后续模型请求。已通过重新校验的其他槽位仍可复用。
4. 异常捕获要贴着缓存校验。保留新模型响应的验证与有限纠正、数据库异常处理、任务尝试上限和最终发布校验。若增加诊断，记录任务 ID、槽位和结构不合法这类元数据即可，避免将 Pydantic 异常里的完整输入直接写入日志。

导入 `ValidationError` 后，缓存分支的改动如下。

```diff
-                    except AppError:
+                    except (AppError, ValidationError):
                         reused = False
```

## 三、回归怎么做

在 [跨版本复用测试](../../../../backend/tests/test_jobs.py#L840) 或 [不合格缓存测试](../../../../backend/tests/test_jobs.py#L997) 附近补一条走真实业务入口的回归。使用隔离 PostgreSQL 和已有模拟 provider。

1. 创建六题准备并完成匹配。首次生成让 `generated-1`、`generated-2` 成功，让 `generated-3` 模拟超时。确认任务停在可重试的第 1 次失败，前两槽已保存。
2. 只在测试夹具里改第 2 槽的工作项，从 `payload["question"]` 移除 `evaluation`。保留 `question` 是字典、关键摘要匹配、验证版本匹配及工作项已验证标记。可以参数化覆盖当前键和历史键，确保用例实际触发结构校验，并另用一个类型错误值覆盖此分支。
3. 调用现有重试 API，传 `expected_attempt=1`。断言第 1 槽复用，模拟 provider 的出题调用依次只有 `generated-2`、`generated-3`。第 3 槽的摘要和禁止列表应来自复用的第 1 题和重新生成的第 2 题。测试可让第 2 题用一条确定且合法的新题干，便于区分实际使用的是哪一版。
4. 断言任务以原 ID 完成第 2 次尝试，数据库第 2 槽已保存完整 `evaluation` 和新内容摘要，最终只发布一份 **3 道题库题 + 3 道 AI 题**的完整计划。
5. 保留已有回归。正常旧缓存仍只生成第 3 槽，题库冲突仍沿用 `AppError` 回退，已用完两次尝试的任务仍不可重试。针对性测试同时覆盖限次和最终发布。
